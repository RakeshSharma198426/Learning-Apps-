- For new features: start with **zerovity-ent-planner** → **zerovity-architect** → **zerovity-tdd-guide**
- For bug fixes: start with **zerovity-build-error-resolver** → **zerovity-ent-code-reviewer**
- For security concerns: always involve **zerovity-security-reviewer**
- For database changes: always involve **zerovity-database-reviewer**
- For documentation: after code changes delegate to **zerovity-doc-updater**
- For end-to-end tests: delegate to **zerovity-e2e-runner**

## Workflow

This project uses the **Zerovity** workflow:
1. `/zerovity:new-project` or `/zerovity:new-milestone` — Start
2. `/zerovity:plan-phase` — Plan a phase
3. `/zerovity:execute-phase` — Execute
4. `/zerovity:verify-work` — Verify
5. `/zerovity:ship` — Ship

Commands are written here as `/zerovity:<name>`. How you run one depends on the tool:

| Tool | Run `plan-phase` as |
|------|-------------------|
| Claude Code | `/zerovity:plan-phase` |
| Cursor | the command file `.cursor/commands/zerovity/plan-phase.md` |
| VS Code + GitHub Copilot, OpenCode | `/zerovity-plan-phase` |
| GitHub Copilot CLI, Codex, Gemini CLI, Antigravity, Kiro | the skill `zerovity-plan-phase` |

## Invariants — enforce on every execute phase (REQUIRED)

This project has a machine-checkable **invariant catalog** at
`.zerovity/invariants/catalog.json`. On platforms with native hooks (Claude Code, Cursor, OpenCode, Kiro)
it is enforced automatically on every file edit. If your tool is not one of those,
you MUST enforce it yourself:

> After making code changes during an execute phase, run:
> `node .zerovity/hooks/lib/invariants.cjs` is the engine; invoke the check with
> `node -e "const e=require('./.zerovity/hooks/lib/invariants.cjs');const r=e.evaluate(process.cwd());console.log(e.renderFailures(r.results)||'invariants OK');process.exit(r.summary.errors?1:0)"`
> Fix every `error`-severity violation before continuing. Treat `warn` as a
> strong signal to address.

## Knowledge graph — use it for every change

Before editing a file, check what depends on it:
`node .zerovity/hooks/lib/graph-query.cjs impact <file>` — `is_hub: true` means high blast radius.
For everything you have changed so far: `node .zerovity/hooks/lib/graph-query.cjs changed`.

If `node .zerovity/hooks/lib/graph-query.cjs status` shows `"stale": true` (or there is no graph),
refresh it first: `node scripts/build-knowledge-graph.js --update`.

When the task is done, run `node .zerovity/hooks/hook-runner.js graph-update` (no-op if nothing changed)
and review any file listed under `affected` that you did not intend to touch.

## Shell

Zerovity workflow snippets are written in bash. They describe what to run, they are not scripts to paste.
If your shell is PowerShell, or a snippet fails to parse, translate it instead of retrying it:
run each `node … zerovity-tools.cjs …` call as written, one per command; read `VAR=$(cmd)` as "remember the output";
read `A || B` as "if A fails, do B"; use your file tools instead of `ls` / `cat` / `grep` pipelines.
Never skip a step because its snippet is bash-only.
